## Follow-up — Reliable native-render capture in the full test suite

The stale-image race is now reproduced and the one-Compose-frame workaround above is superseded. This follow-up changes only `ClockFaceUpdateTest.kt` and this ledger; the production clock fix from item 152 is byte-identical to the start of the follow-up.

Root mechanism: the resolved Compose capture implementation skips forced redraw for Robolectric, assuming synchronous capture. In this project's Robolectric 4.17 / SDK 37 / NATIVE configuration, `ShadowView.areRealDrawTraversalsEnabled()` is true and PixelCopy uses the real surface path. Compose state/semantics becoming idle does not establish that the updated native surface has been committed. Advancing one Compose clock frame is therefore insufficient as a capture barrier. This was checked against the actual runtime JAR bytecode as well as the [Robolectric 4.17 implementation](https://github.com/robolectric/robolectric/blob/robolectric-4.17/shadows/framework/src/main/java/org/robolectric/shadows/ShadowView.java) and [AndroidX Robolectric capture shortcut](https://android.googlesource.com/platform/frameworks/support/+/d3ccab0c1a6b7a31adefc36a2dc3a65791c75270%5E2..d3ccab0c1a6b7a31adefc36a2dc3a65791c75270/).
